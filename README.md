# SECONDACT BOARD

최종 업데이트: 2026-09-04

[인생 2막](https://play.google.com/store/apps/details?id=com.purplusnow.secondactlife2)의
**일별 광고매출 · 인앱매출 · 마케팅비**를 넣으면 누적으로 쌓아 차트로 보여주는 정적 대시보드.
서버도 API 키도 없다. GitHub Pages 위에서 `docs/` 폴더 하나가 전부다.

## 넣는 법

`docs/data/daily.json` 의 `daily` 배열에 하루 한 줄.

```json
{ "date": "2026-09-04", "admob": 4200, "iap": 11000, "ads": 30000 }
```

구글플레이에 찍힌 각국 통화를 그대로 넣어도 된다. 원화 환산은 화면이 한다.

```json
{ "date": "2026-09-04",
  "iap": { "KRW": 11000, "USD": 8.97, "JPY": 600 },
  "admob": 4200,
  "ads": 30000 }
```

숫자만 쓰면 원화, 객체를 쓰면 통화별 금액이다. 손으로 고치는 게 귀찮으면:

```sh
python3 tools/add.py 2026-09-04 --admob 4200 --ads 30000 \
    --iap KRW:11000 USD:8.97 JPY:600

python3 tools/add.py --show          # 최근 기록 확인
```

같은 날짜를 다시 넣으면 **준 항목만** 덮어쓴다(안 준 항목은 그대로 남는다).

## 계산 규칙

숫자를 만지는 곳은 두 군데뿐이고, 둘 다 `docs/data/config.json` 에서 바뀐다.

**환율** — [api.frankfurter.dev](https://api.frankfurter.dev) (ECB 고시)에서 첫 기록일부터
오늘까지를 한 번에 받아 **그날 환율**로 환산한다. 브라우저에 6시간 캐시된다.

- 주말·공휴일은 ECB 고시가 없으므로 **직전 영업일 환율**을 끌어다 쓴다.
- ECB가 다루지 않는 통화(VND, TWD 등)와 API가 죽은 경우는 `fx_fallback` 고정환율로 떨어진다.
  화면 상단 환율 줄에 어느 쪽이 쓰였는지 항상 표시된다.
- 원장에서 `*` 가 붙은 칸이 환산된 값이고, 올려두면 원래 통화와 적용 환율이 보인다.

**스토어 수수료** — `store_fee`(기본 0.15)를 `fee_applies_to`에 적힌 계열(기본 `iap`)에서 뗀다.
광고매출은 이미 실수령액이라 떼지 않는다. 15%/30% 구간 구분은 하지 않는다 — 퉁쳐서 15%다.

## 보는 법

- **일별** — 0선 위가 그날 들어온 돈(광고매출 + 인앱매출), 아래가 나간 마케팅비. 흰 선이 그날 손익.
- **누적** — 세 계열의 누적선 + 누적 손익(흰 굵은 선). 흰 선이 0을 넘은 날이 마케팅비를 다 회수한 날.
- **원장** — 입력값과 계산값. 기간 탭(7/30/90일·전체)은 표시 범위만 바꾸고 누적은 항상 전체 기준이다.

기록이 아직 없을 때 화면이 어떻게 보이는지는 `?demo=1` 로 확인한다 (가짜 데이터, 커밋되지 않음).

## 로컬에서 열기

`file://` 로 열면 fetch가 막힌다.

```sh
cd docs && python3 -m http.server 8731
# http://127.0.0.1:8731/
```

## 배포

`main` 브랜치의 `docs/` 폴더가 그대로 GitHub Pages로 나간다. 푸시하면 끝이고 빌드 단계가 없다.

## 여기 없는 것

설치수·DAU·CPI·LTV·코호트는 일부러 뺐다. 이 대시보드가 답하는 질문은 하나다 —
**지금까지 쓴 마케팅비를 회수했는가.** 그 이상은 GA4/BigQuery 쪽 일이다.
